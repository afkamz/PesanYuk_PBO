**INSTRUKSI FINAL PROJECT**

**PRAKTIKUM PEMROGRAMAN BERORIENTASI OBJEK (PBO)**

**Program Studi:** D3 Teknik Informatika PSDKU Lamongan

**Mata Kuliah:** Praktikum Pemrograman Berorientasi Objek

**Bahasa Pemrograman:** Java

**Waktu Pengerjaan:** 4 Minggu

**Bentuk Pengerjaan:** Kelompok (Maksimal 3 Mahasiswa)

**1. DESKRIPSI TUGAS**

Final Project Praktikum Pemrograman Berorientasi Objek (PBO) merupakan tugas akhir praktikum yang bertujuan untuk mengukur kemampuan mahasiswa dalam memahami dan mengimplementasikan konsep pemrograman berorientasi objek ke dalam sebuah aplikasi sederhana.

Mahasiswa diminta untuk merancang dan membangun sebuah aplikasi berdasarkan permasalahan nyata yang dapat ditemukan dalam kehidupan sehari-hari, lingkungan pendidikan, bisnis, maupun pelayanan masyarakat.

Aplikasi dikembangkan menggunakan bahasa pemrograman Java dengan menerapkan prinsip-prinsip utama Object-Oriented Programming (OOP), meliputi Encapsulation, Inheritance, Polymorphism, dan Abstraction.

Melalui proyek ini, mahasiswa diharapkan tidak hanya mampu menghasilkan aplikasi yang berjalan dengan baik, tetapi juga mampu merancang struktur program yang modular, terorganisasi, dan menerapkan konsep OOP secara tepat.

**2. TUJUAN PEMBELAJARAN**

Setelah menyelesaikan Final Project, mahasiswa diharapkan mampu:

1.  Mengidentifikasi permasalahan dan merumuskan kebutuhan sebuah aplikasi.

2.  Merancang sistem menggunakan pendekatan berorientasi objek.

3.  Mengimplementasikan konsep Class, Object, Constructor, Encapsulation, Inheritance, Polymorphism, dan Abstraction.

4.  Mengimplementasikan Exception Handling untuk menangani kesalahan program.

5.  Mengelola kumpulan objek menggunakan Collection Framework.

6.  Mengembangkan aplikasi Java yang memiliki fungsi sesuai kebutuhan.

7.  Melakukan pengujian, debugging, dan dokumentasi program.

8.  Menjelaskan serta mempertanggungjawabkan implementasi program secara individu.

**3. KETENTUAN PENGERJAAN**

Ketentuan umum Final Project adalah sebagai berikut:

1.  Proyek dikerjakan secara berkelompok dengan jumlah anggota maksimal 3 mahasiswa.

2.  Setiap kelompok wajib menentukan satu judul proyek berdasarkan studi kasus yang dipilih.

3.  Studi kasus dapat dipilih secara bebas, tetapi harus mendapatkan persetujuan dosen pengampu.

4.  Aplikasi wajib dikembangkan menggunakan bahasa pemrograman Java.

5.  Aplikasi dapat berbasis Console atau Graphical User Interface (GUI).

6.  Aplikasi harus menerapkan konsep Pemrograman Berorientasi Objek.

7.  Setiap kelompok wajib membuat dokumentasi desain sistem dan implementasi program.

8.  Setiap anggota kelompok harus memiliki kontribusi dalam pengembangan proyek dan memahami keseluruhan sistem.

9.  Setiap kelompok wajib melakukan demonstrasi aplikasi dan presentasi hasil proyek.

**5. SPESIFIKASI MINIMAL APLIKASI**

Setiap aplikasi yang dikembangkan wajib memenuhi ketentuan berikut.

**A. Spesifikasi Fungsional**

Aplikasi minimal memiliki:

1.  Fitur pengelolaan data (tambah, tampil, ubah, dan hapus).

2.  Fitur pencarian data.

3.  Fitur proses utama sesuai studi kasus.

4.  Fitur validasi input.

5.  Fitur penyimpanan dan pembacaan data.

6.  Fitur penanganan kesalahan program.

Penyimpanan data dapat menggunakan File Handling atau Database.

**B. Spesifikasi Implementasi OOP**

Setiap kelompok wajib menerapkan seluruh konsep berikut:

| **No.** | **Konsep**         | **Ketentuan Implementasi**                                                         |
|---------|--------------------|------------------------------------------------------------------------------------|
| 1       | Class dan Object   | Minimal 5 class yang saling berinteraksi.                                          |
| 2       | Constructor        | Menggunakan constructor dengan parameter.                                          |
| 3       | Encapsulation      | Menggunakan atribut private dan method getter/setter sesuai kebutuhan.             |
| 4       | Inheritance        | Minimal satu hubungan pewarisan antarkelas.                                        |
| 5       | Polymorphism       | Mengimplementasikan method overriding atau penggunaan interface secara polimorfik. |
| 6       | Abstraction        | Menggunakan minimal satu abstract class atau interface.                            |
| 7       | Exception Handling | Menggunakan try-catch dan penanganan kesalahan yang sesuai.                        |
| 8       | Collection         | Menggunakan ArrayList atau Collection Framework lainnya.                           |
| 9       | File Handling      | Mampu menyimpan dan membaca data dari file atau menggunakan database.              |

**Penting:** Penerapan konsep OOP harus sesuai dengan kebutuhan sistem. Mahasiswa tidak diperkenankan hanya menambahkan konsep OOP untuk memenuhi persyaratan tanpa memahami fungsi dan alasan penggunaannya.

**6. TAHAPAN DAN JADWAL PENGERJAAN**

Pengerjaan Final Project dilaksanakan selama 4 minggu dengan tahapan sebagai berikut.

**MINGGU 1 – ANALISIS DAN PERANCANGAN SISTEM**

Aktivitas:

- Menentukan judul dan studi kasus.

- Mengidentifikasi permasalahan.

- Menentukan kebutuhan fungsional aplikasi.

- Menentukan aktor dan proses bisnis.

- Membuat UML Use Case Diagram.

- Membuat UML Class Diagram.

- Menentukan pembagian tugas anggota kelompok.

**Target:** Dokumen analisis kebutuhan dan desain sistem.

**MINGGU 2 – IMPLEMENTASI KONSEP OOP**

Aktivitas:

- Membuat struktur project Java.

- Membuat class dan object.

- Mengimplementasikan constructor dan encapsulation.

- Mengimplementasikan inheritance.

- Mengimplementasikan polymorphism.

- Mengimplementasikan abstraction.

- Mengembangkan logika utama aplikasi.

**Target:** Source code inti dengan penerapan konsep OOP.

**MINGGU 3 – PENGEMBANGAN DAN INTEGRASI APLIKASI**

Aktivitas:

- Mengembangkan fitur-fitur aplikasi.

- Membuat antarmuka aplikasi (Console atau GUI).

- Mengimplementasikan Collection Framework.

- Mengimplementasikan File Handling atau Database.

- Mengimplementasikan Exception Handling.

- Melakukan integrasi antarkelas.

- Melakukan pengujian awal dan debugging.

**Target:** Aplikasi dengan fitur utama yang sudah berjalan.

**MINGGU 4 – PENGUJIAN DAN FINALISASI**

Aktivitas:

- Melakukan pengujian keseluruhan aplikasi.

- Memperbaiki kesalahan program.

- Menyelesaikan dokumentasi.

- Membuat video demonstrasi aplikasi.

- Menyiapkan presentasi.

- Melakukan demonstrasi dan tanya jawab dengan dosen.

**Target:** Aplikasi final, dokumentasi, dan presentasi proyek.

**8. KRITERIA DAN BOBOT PENILAIAN**

Penilaian Final Project menggunakan komponen berikut:

| **No.** | **Komponen Penilaian**              | **Bobot** |
|---------|-------------------------------------|-----------|
| 1       | Implementasi konsep OOP             | 30%       |
| 2       | Fungsionalitas dan kinerja aplikasi | 25%       |
| 3       | Desain UML dan struktur program     | 15%       |
| 4       | Dokumentasi dan pengujian           | 10%       |
| 5       | Presentasi dan demonstrasi          | 10%       |
| 6       | Pemahaman individu                  | 10%       |
|         | **Total**                           | **100%**  |

**Indikator Penilaian**

**1. Implementasi Konsep OOP (30%)**

- Ketepatan penerapan encapsulation.

- Ketepatan penerapan inheritance.

- Ketepatan penerapan polymorphism.

- Ketepatan penerapan abstraction.

- Hubungan dan interaksi antarkelas.

**2. Fungsionalitas Aplikasi (25%)**

- Fitur berjalan sesuai kebutuhan.

- Proses utama aplikasi berjalan dengan benar.

- Validasi input dan penanganan kesalahan.

- Penyimpanan dan pembacaan data.

**3. Desain UML dan Struktur Program (15%)**

- Kesesuaian UML dengan implementasi.

- Pembagian tanggung jawab setiap class.

- Struktur kode yang modular dan terorganisasi.

**4. Dokumentasi dan Pengujian (10%)**

- Kelengkapan laporan.

- Skenario pengujian.

- Bukti hasil pengujian.

**5. Presentasi dan Demonstrasi (10%)**

- Kemampuan menjelaskan aplikasi.

- Kelancaran demonstrasi.

- Kemampuan menjawab pertanyaan.

**6. Pemahaman Individu (10%)**

- Memahami bagian program yang dikerjakan.

- Memahami konsep OOP yang digunakan.

- Mampu menjelaskan alur kerja program.

- Mampu melakukan perubahan sederhana pada kode ketika diminta.

**9. KETENTUAN PRESENTASI DAN TANYA JAWAB**

1.  Seluruh anggota kelompok wajib hadir saat presentasi.

2.  Setiap anggota harus mendapatkan kesempatan untuk menjelaskan bagian aplikasi.

3.  Dosen dapat menunjuk anggota kelompok secara acak untuk menjelaskan bagian tertentu dari source code.

4.  Dosen dapat meminta mahasiswa menunjukkan implementasi konsep OOP secara langsung.

6.  Nilai individu dapat berbeda meskipun mahasiswa berada dalam kelompok yang sama.

**10. KETENTUAN TAMBAHAN**

1.  Mahasiswa wajib mengembangkan aplikasi secara mandiri dan bertanggung jawab atas source code yang dikumpulkan.

3.  Setiap kelompok wajib melaporkan perkembangan proyek sesuai tahapan yang telah ditentukan.

4.  Keterlambatan pengumpulan mengikuti ketentuan dosen pengampu.
